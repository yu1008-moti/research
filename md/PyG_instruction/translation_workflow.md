## 概要

このファイルは，「PyG公式ドキュメントの特定ページをフェッチ → 日本語訳（数式のMarkdown対応込み）→ `.\md\PyG_instruction\<No.>_*.md` として出力する」という，このディレクトリで繰り返し行うタスクの作業手順を，自分自身（Claude Code）向けに書き残したものである．
次回以降，同種の依頼（PyGドキュメントのURLを渡されて翻訳・出力する）を受けたときは，このファイルの手順に従う．

## 手順1：URLから内容を取得する

### なぜ WebFetch だけに頼らないか

`WebFetch` ツールは内部で小型モデルによる要約を行うため，`Return the full page content verbatim` のように強く指示しても，"The tutorial covers..." のような **メタ的な要約文** に化けてしまうことがあった（コードブロックが丸ごと欠落するケースあり）．
実際に `dataset_splitting.html`・`neighbor_loader.html` で発生を確認済み．プロンプトを工夫して再試行すれば verbatim に近い結果が得られることもあるが，安定しない．

### フォールバック手順（curl + 自前パーサ）

`WebFetch` の結果が要約や省略になっている疑いがある場合は，次の手順で生HTMLから直接テキストを抽出する．

1. `Bash` ツールで `curl -s -A "Mozilla/5.0" <URL> -o <scratchpad>/<name>.html` によりHTMLをスクラッチパッドへ保存する．
2. PyG公式ドキュメント（readthedocs / sphinx_rtd_theme）は本文が `itemprop="articleBody"` を持つ `<div>` に入っている．これを確認してから抽出する．
3. 環境に `pandoc` や `beautifulsoup4`（`bs4`）が入っていない前提で，Python標準ライブラリ `html.parser.HTMLParser` を使った簡易抽出スクリプトをスクラッチパディレクトリに書き，見出し・段落・`<pre>`（コードブロック）・リスト・リンク・強調をMarkdown相当のテキストへ変換して別ファイルへ書き出す．
   - Windows環境では `print()` で日本語やUnicode特殊文字（`\uf0c1` など）を出力すると `cp932` コーデックでエラーになるため，**必ず `encoding='utf-8'` を指定してファイルへ直接書き込む**（標準出力へ`print`しない）．
4. 抽出結果を `Read` で読み，見出し・コード・リンク・数式が欠落なく含まれているか目視確認する．

この方法で `neighbor_loader.html`・`explain.html`・`graph_transformer.html` の完全なverbatimテキスト（コードブロック・数式・表を含む）を取得できた．

## 手順2：取得内容を検証する

- コードブロックの中身が省略・要約されていないか（`...` で端折られていないか）．
- 数式（`\( \)` や `\[ \]`）や表（Sphinxのdefinition list形式の疑似テーブル）が失われていないか．
- リンクURL（`../modules/...` のような相対パス）が保持されているか．

疑わしい場合は手順1のフォールバックに切り替える．

## 手順3：既存ファイルの体裁を確認する

翻訳ファイルを書く前に，同ディレクトリの既存ファイル（例：[03_heterogeneous_graph_learning.md](03_heterogeneous_graph_learning.md)）を1つ `Read` し，次の体裁に合わせる．

- 1行目：`# <英語の原題>`（原題はそのまま英語で残す）
- 2行目以降：目次（原文の見出し構造に対応する箇条書きリンク，ネストはインデントで表現）
- 目次の後に `---` で区切り線
- 見出しは原文の英語見出しをそのまま使う（`## Neighbor Sampling` など）．本文のみ日本語訳する
- コードブロックは `python` 言語指定付きのフェンスのまま，コード自体は翻訳しない（コメントも含め英語のまま）
- 原文の `Note` / `Warning` 注釈ボックスは `> **Note**` / `> **Warning**` の blockquote に変換する
- 原文中のリンク（`[text](url)`）はURLをそのまま保持する

## 手順4：日本語へ翻訳する

- 見出し以外の説明文・注釈・リストは日本語に翻訳する．
- 変数名・クラス名・関数名・コード中の識別子は翻訳しない（`NeighborLoader`，`batch_size` など）．
- 論文タイトルなど固有名詞的な引用符付きの英語表現は，原文のまま `[“...”](url)` の形で残す．
- 出力の言語ルールは [CLAUDE.md](../../CLAUDE.md) の「Language used to display plain texts is Japanese」に従う．

## 手順5：数式記法をMarkdown向けに変換する

PyG公式ドキュメントはSphinx/MathJaxビルドのため，数式が `\(...\)`（インライン）・`\[...\]`（ディスプレイ）というLaTeX記法で書かれている．
これをそのまま転記すると，VSCodeの標準Markdownプレビューや多くのMarkdownレンダラでは正しく表示されない（`$...$` / `$$...$$` を期待するため）．

**変換ルール：**

- インライン数式：`\(...\)` → `$...$`
- ディスプレイ数式：`\[...\]` → `$$...$$`

**注意（実運用で踏んだ罠）：**

- Git Bash の `sed` で `s/\\(/$/g` のような置換を試みると，バックスラッシュのエスケープ解釈の違いで `sed: -e expression #1, char 9: Unmatched ( or \(` のようなエラーになることがあった．
- 確実なのは `Bash` 経由で **Python のワンライナー/ヒアドキュメント** を使い，単純な文字列 `str.replace()` で置換すること（正規表現不要，エスケープ地獄を回避できる）．

```python
path = "c:/Users/togen/research/md/PyG_instruction/<file>.md"
with open(path, encoding='utf-8') as f:
    text = f.read()
text = text.replace('\\[', '$$').replace('\\]', '$$')
text = text.replace('\\(', '$').replace('\\)', '$')
with open(path, 'w', encoding='utf-8') as f:
    f.write(text)
```

- `\[` → `$$` を先に処理してから `\(` → `$` を処理すること（両方が混在するファイルでは順序に注意）．
- 変換後は `Grep` で `\\\(|\\\)|\\\[|\\\]` をディレクトリ全体に対して検索し，取りこぼしがないか確認する．

## 手順6：ファイル名を決めて出力する

- `Glob` で `md/PyG_instruction/*.md` を確認し，既存ファイルの最大の連番（`00`〜）の次の番号を採番する．
- ファイル名は `<2桁連番>_<内容を表す英語スラッグ>.md`（例：`06_scaling_gnns_neighbor_sampling.md`）．スラッグは原文タイトルを踏まえて簡潔に決める．
- `Write` ツールで手順3〜5を反映した内容を書き込む．

## 手順7：後片付け

- `curl` で保存したHTMLや自作抽出スクリプトなど，スクラッチパディレクトリに置いた中間ファイルは，タスク完了後に削除する（プロジェクトディレクトリを汚さないため）．
